# 2.0.0 升级与数据迁移

2.0.0 是浏览器扩展的固定 ID 主版本。它通过 GitHub Release 提供 ZIP 安装包，不通过 Chrome Web Store 发布。

如果你从 1.x 升级，推荐按“本地备份迁移为主、WebDAV 备份兜底”的顺序操作。不要先卸载旧版，也不要先清理浏览器扩展数据。

最简流程是：

1. 在旧版手动导出本地 ZIP 备份。
2. 如已配置 WebDAV，再额外上传一份 ZIP 备份。
3. 安装 2.0.0，优先使用本地 ZIP 导入。
4. 确认导入结果后，再保留或移除旧版。
5. 只有本地文件损坏、丢失或导入异常时，才使用 WebDAV 备份恢复。

## 先判断你是否需要迁移

- **同一个扩展 ID 的普通更新**：浏览器通常会保留本地数据，不需要重复迁移；仍建议在更新前导出备份。
- **从 1.x 切换到 2.0.0 固定 ID**：需要手动导出和导入。Chrome 不会在两个扩展 ID 之间自动搬运 `chrome.storage` 和 IndexedDB 数据。
- **更换浏览器、用户目录或设备**：也建议使用本页的备份流程，不能只依赖浏览器自动保留数据。

## 升级前备份

1. 暂时保留旧版扩展，不要卸载或清除扩展数据。
2. 打开旧版管理面板的 `备份与恢复`。
3. 在“本地备份”区域点击“导出 ZIP 备份”。
4. 将下载的 `javdb-extension-backup-日期时间.zip` 保存到管理面板以外的位置。这是本次升级的主备份；历史版本的 JSON 备份仍可导入。
5. 如果已经配置 WebDAV，再执行一次“立即上传至云端”。WebDAV 会额外保存一个 ZIP 备份，作为本地文件之外的第二份恢复点。

本地 ZIP 和 WebDAV 备份都可能包含连接配置中的敏感信息，例如 Cloud 账号密码、Emby/Jellyfin API Key 或访问令牌。备份 ZIP 是数据备份格式，不等同于本次 Release 安装包的解压密码，也不应把备份密码写入公开文档。请像保管密码一样保管备份文件，不要上传到公开仓库、公开网盘或 Issue。

## 安装 2.0.0

1. 从 [JavdBviewed 扩展 Release](https://github.com/JavdBviewed/JavdBviewed/releases) 下载 2.0.0 ZIP。
2. 使用安装包密码 `我已备份数据` 解压到一个固定目录，不要直接从压缩包内加载；如果系统自带工具无法解压密码 ZIP，请使用 7-Zip、Bandizip 等工具。
3. 打开 Chrome 或 Edge 的扩展管理页：`chrome://extensions/`。
4. 开启“开发者模式”，选择“加载已解压的扩展程序”。
5. 选择解压后的 2.0.0 目录，确认新扩展可以打开管理面板。

安装完成后，旧版和 2.0.0 可能会同时存在。这是正常的迁移保护状态；在验证完成前请保留旧版。

## 导入本地备份

1. 在 2.0.0 管理面板打开 `备份与恢复`。
2. 在“本地备份”区域点击“导入本地备份”，选择刚才保存的 ZIP 文件；历史 JSON 备份也可以直接选择。
3. 查看导入预览中的备份版本、备份时间和数据数量。
4. 确认导入后等待结果提示，再刷新管理面板。
5. 按下面的清单检查数据是否恢复。

旧版备份格式会自动迁移到当前格式。导入失败、JSON 损坏或部分类别写入失败时，页面会显示错误；不要在旧版数据未保留的情况下反复覆盖导入。

## 本地导入失败时使用 WebDAV 兜底

WebDAV 恢复是可行的，但建议只在本地 ZIP 不可用或导入异常时使用。它不是本地导入的前置条件，也不应该成为唯一备份。

1. 保留旧版扩展和原有浏览器数据，不要继续执行清空或重置操作。
2. 在 2.0.0 中打开 `设置 → WebDAV 同步`，手动填写旧版使用的 WebDAV 地址、账号、密码和远程路径。
3. 保存并测试连接，确认能看到旧版上传的 `javdb-extension-backup-日期.zip`。
4. 打开 `备份与恢复`，选择“从云端恢复”。
5. 选择升级前的 ZIP 备份，先查看备份时间和数据范围。
6. 优先开启“恢复前自动备份”；按需要选择合并或覆盖，再确认恢复。
7. 恢复完成后检查番号、观看状态、演员、清单和设置，再重新验证 Cloud、115、Emby/Jellyfin 等连接。

由于 2.0.0 是新的扩展 ID，旧版保存的 WebDAV 配置不会自动出现在 2.0.0 中。如果本地 ZIP/JSON 都无法导入，必须先手动填写 WebDAV 连接信息；没有连接信息或可访问的 WebDAV 备份时，无法仅凭新扩展 ID 找回旧数据。

## 哪些数据会迁移

默认完整备份会覆盖或恢复可持久化的业务数据，包括：

- 扩展设置和用户资料
- 番号记录、观看状态、观看进度和用户标签
- 演员库、新作品订阅与记录
- 清单、系列、标签和磁链缓存
- 媒体库来源、媒体副本清理状态和删除历史
- Cloud、115、Emby/Jellyfin、WebDAV 等已保存的连接配置
- 日志、报告和导入统计等可恢复数据

以下内容不作为迁移目标：

- 当前登录会话、刷新中的任务状态（已保存到连接配置中的参数按备份策略处理）
- Cloud/同步队列游标、运行时锁和浏览器页面状态
- 图片、头像、封面等可重新获取的缓存
- 尚未完成的后台任务现场

因此，导入连接配置后，Cloud、115 或媒体服务器可能需要重新验证登录；这不代表迁移失败。

## 导入模式和重复导入

从“本地备份”选择 ZIP 或 JSON 并确认的完整导入，当前按覆盖模式执行，会写入备份中包含的类别。重复导入同一份备份不会创建重复记录，但仍会再次覆盖这些类别；因此每次导入前都应确认选中的文件正确。

从 WebDAV 恢复时，可以按类别选择“合并”或“覆盖”。合并会保留本地独有记录，并按记录时间处理同一条记录；覆盖会用备份内容替换所选类别。覆盖前建议先导出当前数据，因为恢复操作会改变本地内容。

WebDAV 恢复默认建议开启“恢复前自动备份”。这样即使选错备份，也可以返回恢复结果中的回滚点。

## 升级后检查清单

- 番号库数量和几个已知番号的观看状态正确。
- 演员库、清单、标签和新作品订阅可以打开。
- 媒体库来源仍然存在，详情页和播放入口可用。
- Cloud、115、Emby/Jellyfin 的连接配置已保存；需要时重新登录或刷新凭证。
- WebDAV 配置和最近一次备份时间正确。
- 设置中的主题、页面增强和隐私保护选项符合预期。
- 在新版本中再导出一份备份，作为迁移完成后的基线。

确认以上内容后，才建议移除旧版扩展。不要通过删除整个 Chrome 用户目录来回滚，这可能同时删除旧版仍在使用的数据。

## 导入失败或需要回滚

1. 停止在 2.0.0 中继续导入、清空或重置操作。
2. 保留失败提示、备份文件和当前版本信息，不要公开上传包含凭据的日志或备份。
3. 重新打开旧版扩展，确认原有数据仍在，并再次导出一份本地备份。
4. 修复文件或环境问题后，再在 2.0.0 中导入。
5. 如果暂时不继续升级，关闭 2.0.0 管理面板，使用旧版扩展继续工作。

如果旧版数据已经被清理，优先尝试 WebDAV 中最近一次成功备份；没有备份时，浏览器无法从新扩展 ID 自动找回旧数据。
