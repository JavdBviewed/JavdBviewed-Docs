# Android 媒体库与本地文件

本文以公开可下载的 **Android 1.0.2（`mobile-v39`）** 为日常操作基线。底栏的 **媒体库**、**资源库** 与 **我的 → 下载中心** 展示的内容来源不同：云端索引、远端影片列表、手机上的下载文件不能互相替代。首次使用先看[安装与登录](/mobile/install)，接入源见[连接媒体源](/mobile/sources)。

## 先分清三个列表

| 入口 | 1.0.2 中显示什么 | 想播放时从哪里开始 |
| --- | --- | --- |
| **媒体库** | 从可用媒体源取得的影片、继续观看、最新，以及同步来的只读 Cloud 索引 | 对可访问的媒体源影片点开详情再播放 |
| **资源库** | 手机上的已保存媒体源，包括“本地下载”；目录型源可逐级浏览 | 打开具体源，选择可访问的视频文件 |
| **我的 → 下载中心** | 下载任务及排队、进行中、失败或完成状态 | 先确认已完成，再去“本地下载”源找文件 |

**Cloud 索引只是影片资料**：1.0.2 的媒体库会展示“云端索引 · 只读”区块，但点这个索引条目不会当成实际播放地址。想看片还要找到手机当前网络可访问的 Emby/Jellyfin 等源，或者手机里真正存在的视频文件。Cloud 登录成功不表示源服务器在线，也不表示视频被下载到了手机。

## 在 1.0.2 的媒体库浏览

1. 先到 **资源库** 核对媒体源是否已保存；需要时按[媒体源指南](/mobile/sources)添加并测试连接。
2. 到 **媒体库** 查看 **全部影片**；可以使用页面上的搜索输入、**刷新**，或返回页面触发重新加载。等待列表加载完成后再判断是否为空。
3. 找到实际来自可访问媒体源的影片，点开详情，再按 **播放** 或 **下载**。源的账号失效、网络断开或文件移走时，列表中的条目也可能无法播放。
4. **继续观看** 与 **最新** 是单独的入口；栏目里有没有条目取决于对应记录和源数据，不代表所有本机文件都应在这里显示。

搜索后看到的“全部影片”可能显示为“搜索：关键词”；清空搜索词，再点 **刷新**，才能核对未筛选的列表。**专辑**和**排序**也是媒体库中的操作，不会把尚未下载的视频复制到手机。

如果列表提示“暂无影片”，先核对资源库是否已有源、源是否可访问，以及 Cloud 是否同步到预期实例；刷新仍为空时，不要反复清除应用数据。媒体库遇到剧集类条目时，1.0.2 的页面可能提示“剧集功能暂未开放”；不要把这一提示解释为下载文件丢失。

## 在 1.0.2 找已下载视频

1. 从 **我的 → 下载中心** 确认对应任务已完成。“已加入下载”只代表任务入队，未完成时没有可用于本地播放的完整文件。
2. 到 **资源库** 找 **本地下载** 源；1.0.2 在本机建立此源，保存应用的下载文件。点进源的目录后选具体文件播放。
3. 本地下载源只列出目录或受支持的视频文件；如果列表为空，核对任务是否完成、文件是否仍存在、格式是否受支持，而不是只检查 Cloud 登录状态。
4. 不要为了“整理列表”随意删除下载任务：该版本的任务删除操作也会尝试删除对应的已下载文件。暂停、重试和下载故障见[播放与下载](/mobile/playback)。

排查时先问自己要找的是**下载任务**还是**已经存在的文件**：任务的进度在下载中心，文件要在“本地下载”源里确认。再次进入“媒体库”或按“刷新”，不会替代下载任务完成，也不会修复源文件已被删除的问题。

“本地文件”是另一种源：可以在[媒体源设置](/mobile/sources)中通过 Android 目录选择器授予本机文件夹读取权限；**本地下载**则指应用自己的下载目录。两者都不等于电脑上的目录，也不因 Cloud 登录自动复制给其他设备。

> [!IMPORTANT]
> **1.0.2 不保证已下载文件自动出现在“媒体库 → 全部影片”。** 在当前可核的安装包中，应先从资源库的“本地下载”源浏览、播放。下载中心显示“完成”与媒体库聚合是两件事，不要把未出现在“全部影片”直接当作下载失败。

## 1.0.3 变化：仅源码与发布说明可核

1.0.3 的源码和发布说明描述：当 `local_download` 源有视频文件时，**媒体库 → 全部影片** 会聚合这些本地下载条目；点击条目直接解析本地文件并打开播放器，不经过 Emby 详情页。没有该源或目录为空时，原有列表行为保持不变。

这一变化**不扩展到**“剧集”“继续观看”或“最新”入口；即使以后安装到了经核实的 1.0.3，已下载影片只在“全部影片”可见、其他栏目不显示也不应直接当作故障。使用搜索时同样先回不带筛选条件的“全部影片”检查，不要根据搜索结果推定本机文件已不存在。

但截至 **2026 年 11 月 6 日**，发布仓的当前清单虽标为 **1.0.3 / `mobile-v42`**，公开 Release 与对应 APK 链接却返回 404。**当次未核到公开可安装的 1.0.3 包**；以上是版本说明及固定源码的行为介绍，不是建议下载未核实安装包，也不能用它替代 1.0.2 的操作步骤。版本和安装边界见[安装与升级](/mobile/install)。

## 找不到影片时怎么查

| 现象 | 先确认 |
| --- | --- |
| “全部影片”为空 | 源是否已经添加、启用并从当前手机可访问；点 **刷新** 再看，核对搜索条件 |
| 看到云端索引但点不开 | 索引是只读资料；找到对应的可访问媒体源，不能直接从索引起播 |
| 下载任务已完成，“全部影片”没有该文件 | 在 1.0.2 是预期的版本边界；到 **资源库 → 本地下载** 浏览 |
| “本地下载”也没有文件 | 核对任务状态、文件是否被删除或移走，以及视频格式是否可识别 |
| 本机文件能在目录里找到但无法播放 | 先检查文件本身与目录读取权限，再看播放器的错误提示 |
| “继续观看”没有下载的影片 | 不把“全部影片”“继续观看”当同一列表；从本地下载目录定位文件 |
| 其他设备看不到手机的下载 | 下载是本机文件；Cloud 索引或播放进度同步不会替你上传视频文件 |
