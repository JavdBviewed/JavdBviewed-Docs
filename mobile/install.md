# 安装与升级 Android 应用

本文针对原生 Android 应用的 **1.0.2（`mobile-v39`，versionCode 39）**。截至 **2026 年 11 月 6 日**，这是已核实公开 Release 有 APK 资产的稳定版本。安装完成后需要连接自己的 Cloud 并登录，才能进入主界面；首次使用路线见[Android 指南](/mobile/)。

> [!WARNING]
> 目前发布仓库的**当前** `manifests/mobile/stable.json` 写着 1.0.3（`mobile-v42`），但公开 `mobile-v42` Release 和 APK 链接在上述核查日期返回 404。**不要把清单状态当作 APK 已可下载的证明**；下面的安装入口和哈希均指已公开的 `mobile-v39`，绝不用于校验 1.0.3。

## 安装前确认

- 固定发布源码为 Android `minSdk 26`；设备低于 **Android API 26** 时不能安装该 APK。设备的系统版本和 CPU 架构可以从其系统信息或可信的设备规格核对，不要仅凭手机品牌推断。
- 需要访问自己的 Cloud 实例：先准备从手机网络可到达的 Cloud 地址及实例账号和密码。**Cloud 登录页是 1.0.2 首次启动的必经入口**。
- 准备足够空间下载和安装 APK；如打算播放或下载影片，还需单独准备手机可访问的媒体源，不能把 Cloud 地址当成影片源。
- 升级已有应用前，先确认 Cloud 同步状态，备份尚未同步的重要数据与本地下载文件；**不要先卸载旧版**，卸载可能移除本机应用数据。

## 按 ABI 选择一个 APK

打开[官方 `mobile-v39` Release](https://github.com/JavdBviewed/JavdBviewed-release/releases/tag/mobile-v39)，在 Assets 中按设备支持的 ABI 下载**一个**安装包及其同名 `.sha256` 校验文件：

| 设备支持的 ABI | 安装包文件名 | 选择建议 |
| --- | --- | --- |
| `arm64-v8a` | `app-arm64-v8a-release.apk` | 支持该 64 位 ARM 架构时选它 |
| `armeabi-v7a` | `app-armeabi-v7a-release.apk` | 使用该 32 位 ARM 架构时选它 |
| `x86_64` | `app-x86_64-release.apk` | 支持该 64 位 x86 架构时选它 |
| 无法确认 | `app-universal-release.apk` | 包含多种架构，文件更大；不确定时选它 |

这四种是**一个版本的不同打包方式**，不需要全装。`x86_64` 通常用于对应架构的设备或模拟器；不要因为它的文件名中有“64”就给 ARM 手机安装。发布页里的 `.sha256` 是校验文件，不是安装程序。

不要从 `mobile-v42` 的 1.0.3 清单复制下载地址，也不要用 1.0.3 哈希校验 1.0.2 APK。公开 Release 资产有变更时，应先核实版本、文件名和校验文件确实对应，再决定安装。

## 核对下载内容

下载同版 APK 和同名 `.sha256` 后，在支持 SHA-256 的工具里计算 APK 哈希，并与校验文件对照。若先在 Windows 电脑上下载，可以在文件所在目录打开 PowerShell，例如：

```powershell
$file = '.\app-arm64-v8a-release.apk' # 换成实际下载的 APK 文件名
(Get-FileHash -LiteralPath $file -Algorithm SHA256).Hash.ToLowerInvariant()
```

历史 `mobile-v39` 稳定清单也记录了这四个**1.0.2** APK 的预期 SHA-256；用来核对自己选中的**同名**文件：

| APK | SHA-256（1.0.2 / `mobile-v39`） |
| --- | --- |
| `app-arm64-v8a-release.apk` | `16e1b1c651d7a486503ea94aec8e6f415dc04ff2ff72b05091eac5a48925fb87` |
| `app-armeabi-v7a-release.apk` | `3d2bdf9d1a8f9fcb7a63321bcfedcc10b512b97ddcd649f887b613da4ae26171` |
| `app-x86_64-release.apk` | `59678d0e2e602a8e59eaa821eefaef77313fff16273c2bd99bb9df60e39cae71` |
| `app-universal-release.apk` | `7969015fcb261b01df4836ac6119f16048b3cc7ff21f5bc19e40c14403bc0862` |

**哈希不一致时停止安装。**检查是否拿错版本、ABI、文件名或未下载完整；从同一官方 Release 重新下载并复核，不能忽略差异。哈希匹配证明文件与清单一致，仍要核对下载来源是否为官方 Release。

## 安装与首次打开

1. 在 Android 设备上打开已校验的 `.apk`，按照系统提示安装。通过浏览器或文件管理器打开 APK 时，系统可能要求为**这一个来源应用**允许安装未知应用；只对当前可信来源临时授权，不要关闭系统整体防护。
2. 若曾临时允许该来源安装，完成后可回到 Android 设置撤销该来源的安装权限；不同设备的菜单文字和位置可能不同，以系统实际提示为准。
3. 打开 JavdBviewed，填写自己的 Cloud 服务器地址、账号及密码并登录。示例地址 `https://cloud.example.com` 只是格式占位，不提供公共 Cloud 服务。
4. 登录成功进入主界面后，到 **资源库** 查看或添加媒体源，再在 **媒体库** 浏览影片；网络与媒体源是不同连接。详情见[连接媒体源](/mobile/sources)。

没有已核实的 iOS 或 TV 正式安装包。不要把 `apps/mobile` 骨架、模拟器包或第三方 APK 当作对应平台的官方发行版。

## 覆盖升级现有安装

1. 先确认已安装应用的版本；只有发布页和资产均可核、且 `versionCode` 高于当前安装时，才按新版说明升级。当前 1.0.3 资产不可核实，不能按本地清单直接升级到它。
2. 确认 Cloud 同步反馈并备份重要本机数据；本地下载文件和未同步记录不能仅凭“已经登录 Cloud”就视为已备份。保留原安装包及其哈希，直到新版本使用正常。
3. 选对架构、来源与哈希后，**不卸载原应用**，直接运行官方新版 APK，让 Android 尝试覆盖升级。应用标识相同且签名与已安装版本一致，是覆盖安装的前提；如果系统报签名不一致，不要通过先卸载来绕过。
4. 升级后核对 Cloud 登录、资源库条目、本地文件及下载任务，再验证一部影片能否播放；如新版说明要求额外迁移，以该版正式说明为准。

无法覆盖安装时，先保留旧应用和数据，核对是否下载了官方同签名、更高 `versionCode` 的对应架构 APK。**卸载重装不等于安全回退**；旧版本也未必能读取升级后写入的数据。需要回退时保存问题与当前版本信息，先评估已有备份，不要贸然清空应用存储。

## 安装问题

| 现象 | 优先检查 |
| --- | --- |
| 提示设备不兼容 | 系统是否达到 API 26、设备 ABI 是否匹配；不确定时用同版 universal APK |
| 提示禁止安装此来源 | 仅按系统提示给打开 APK 的来源应用授权，安装后可撤销；不要关闭安全防护 |
| 提示签名冲突或无法覆盖 | 旧版与新 APK 是否同一官方来源及签名；保留旧版数据，勿先卸载 |
| 校验值不一致 | 是否混用 1.0.2 与 1.0.3 的 APK/哈希，或文件下载不完整；停止安装并重新核对 |
| 安装后停在 Cloud 登录页 | 这是首次进入主界面的要求；检查 Cloud 地址、网络与实例账号，不要为此清除应用数据 |
