# 连接 Android 媒体源

本文按公开可获取的 **Android 1.0.2（`mobile-v39`）** 编写。手机端要先连接自己的 Cloud 并登录，才能进入主界面；进入后在底栏打开 **资源库** 添加或查看媒体源。**Cloud 登录、作品记录同步与远端视频访问不是同一条通道**：能登录 Cloud 不代表 Emby、文件共享或 115 的视频在手机网络下可播放。

首次安装与登录见[安装与首次登录](/mobile/install)。以下操作针对 Android 原生客户端，不套用桌面端的“媒体源连接”设置页。

## 选择已经实现的源

1.0.2 的 **添加源** 表单里，下列类型有实现路径，但各自的连接、浏览和播放方式不同：

| 类型 | 准备什么 | 保存后从哪里查看 |
| --- | --- | --- |
| **Emby / Jellyfin** | 从手机可访问的媒体服务器地址、该服务的账号密码或 API Key | **媒体库**浏览影片；在资源库点源条目可回到配置 |
| **SMB** | 网络共享的服务器和共享目录地址、所需账号密码 | **资源库**点该源，逐级浏览目录 |
| **WebDAV** | 服务端的 WebDAV 地址及所需账号密码 | **资源库**点该源，逐级浏览目录 |
| **本地文件** | 手机上的目录；优先使用“选择本地目录”授予访问权限 | **资源库**点该源浏览文件 |
| **115** | 可用的扫码登录能力与自己的 115 账号 | **资源库**点已建立的源浏览 |

**本地下载**是与下载文件关联的源类型，不是让你填写 Emby 地址的另一种网络服务。详见[媒体库与本地文件](/mobile/library)。下拉列表中还保留“即将支持”的其他类型；它们不能因为名字可见就当作已经能添加、浏览或播放。1.0.3 清单虽然存在，但公开 Release 和 APK 当次不可核，不能借其文案推断 1.0.2 还有新功能。

## 添加 Emby 或 Jellyfin

1. 在 **资源库** 点右下角的 **添加源**，类型选 **Emby** 或 **Jellyfin**。
2. 填 **显示名称**（方便辨认）和 **服务器地址**，例如 `https://media.example.com`。示例地址不可用；换成从**这部手机**当前网络可访问的媒体服务器根地址，保留实际需要的端口。
3. 填媒体服务器自己的**用户名**与**密码**；如果使用该服务器的 API Key，则填表单中的 **API Key（可选）**。Cloud 账号密码不要填到媒体服务器表单。
4. 点 **测试连接** 查看反馈，再点 **测试并保存**。返回资源库后核对列表中的源名称和最近测试状态。
5. 打开 **媒体库**，确认能加载服务器上该账号可访问的影片；选择一部已知可播放的影片试播。仅能保存配置不等于媒体服务返回了可用视频地址。

用用户名和密码时，固定版本会请求媒体服务器的登录接口。**仅使用 API Key** 时，测试结果可能提示“连接配置已保存，稍后校验 API key”，这不是已经实际验证该 Key 能列片或播放的证明；仍需到媒体库验证。编辑已有条目时若凭据失效，请按实际需要重新填写、测试；不要把未显示密码等同于媒体服务器无需认证。

> [!TIP]
> 同一地址在 Cloud 设置中用于登录自己的数据服务，在媒体源表单中则要指向影片服务器。Cloud 同步过来的 Emby/Jellyfin 配置可在手机本地列表出现；它可能带来源凭据，也仍需从**当前手机网络**测试服务器可达性。

## SMB、WebDAV 和本地目录

- **SMB**：选择 SMB 后，地址形如 `smb://files.example.com:445/share/path`。这里的主机只是格式示例。填写对应共享账户和密码，点 **测试连接**；若不通，先确认手机能连到局域网或授权网络，以及服务器、端口、共享名与账号权限。
- **WebDAV**：填写实际 WebDAV 服务地址，例如 `https://files.example.com/dav/`，按服务要求填写账号密码；测试通过后仍要进入目录确认文件可列出并可读取。连接测试成功不保证所选影片有可播放的资源地址。
- **本地文件**：选择本地文件类型，点 **选择本地目录**，在 Android 的目录选择器中选取手机可访问的文件夹并授予读取权限。这个选择会填入目录 URI；不要将 Windows 盘符、Cloud 网址或 Emby 地址当作 Android 本地路径。移走目录或撤销授权后，需要重新检查权限。

这三类源在 **资源库** 点保存的源条目后进入目录浏览页；在目录中选择具体文件。网络共享目录在家中 Wi-Fi 可用但移动网络不可用时，应先确认连接方式、服务器是否对该网络开放，不要仅因 Cloud 能登录就假定 SMB/WebDAV 路径也能连接。

## 115 登录与凭据

选择 **115** 时，普通表单的“测试连接”和“测试并保存”按钮不会像 Emby 那样用于直接登录；应使用 **115 扫码登录** 入口，按页面提示用自己的账号确认。固定 tag 的扫码功能依赖发布构建提供 `client_id`；若界面提示“未配置 115 client_id，登录功能暂不可用”，说明**本次构建无法通过扫码入口登录**，不要编造默认密钥或粘贴他人的令牌。

从 Cloud 同步的 115 配置和本机已保存配置也可能不同；如果页面提示“Cloud 未同步 115 配置，当前使用本地配置”，先核对连接到的实例、同步状态和自己的 115 登录状态。请仅在自己的设备管理账户凭据，不要在截图、公开 issue、文档或 URL 示例中展示真实 cookie、token、二维码、账号和密码。

## Cloud 导入和媒体访问的边界

Android 1.0.2 登录 Cloud 后，可从同步的设置里导入 **Emby/Jellyfin** 媒体服务器条目；列表中“来自 Cloud 同步”说明配置来源，**不是本机已经连通服务器的实测结果**。如果该服务器仅在另一台电脑的局域网可达，手机换网络后仍可能打不开。Cloud 还会同步自己的作品记录或索引；索引可见不等于 Cloud 保存了视频文件，更不等于手机已下载了视频。

手机本地填写的 SMB、WebDAV 或目录 URI 需要按当前设备的路径、账户和授权分别核对，不要假定会因 Cloud 登录自动在其他设备上变得可用。已登录仍需手动添加或核对媒体源时，进入 **资源库** 操作，不需要重新安装 APK。

## 排查顺序

| 表现 | 先检查 |
| --- | --- |
| 无法进入资源库 | 是否已登录自己的 Cloud；核对 Cloud 地址、网络与实例账号 |
| 资源库为空 | 点右下角添加源；若预期从 Cloud 导入，核对同步反馈以及远端是否确有媒体服务器设置 |
| 类型在下拉列表中但不可保存 | 是否标为“即将支持”；选择已实现类型，不要用名称推断可用性 |
| Emby/Jellyfin 测试失败 | 服务器根地址、端口、账号权限和**手机**当前网络是否可达 |
| API Key 提示稍后校验 | 此提示不证明能列片；到媒体库核对影片并试播 |
| SMB/WebDAV 连接后打不开文件 | 共享路径、目录权限、网络访问及具体文件是否可读 |
| 本地目录列表为空 | Android 是否授予该目录读取权限；目录内是否有可识别的文件 |
| 115 无法扫码 | 是否显示 `client_id` 未配置；不要公开令牌或尝试他人账号 |
| 云端有影片信息但播放失败 | 媒体源及视频文件是否仍可从手机访问；Cloud 索引不是播放地址 |

视频播放与下载见[播放与下载](/mobile/playback)，本地文件和媒体库的区别见[媒体库与本地文件](/mobile/library)；返回[Android 使用指南](/mobile/)。
