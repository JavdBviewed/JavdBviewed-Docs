# 更新桌面端

本文适用于已安装的 **Windows x64 桌面端 1.0.0**。更新前先确认正式发布状态、保留自己的数据，再使用对应版本的安装程序。源码主分支中的新界面或操作不等于稳定版已经提供；发布版本与资产以[正式稳定发布清单](https://github.com/JavdBviewed/JavdBviewed-release/blob/main/manifests/desktop/stable.json)和对应 Release 为准。

> [!IMPORTANT]
> 1.0.0 **不会自动检查更新**。应用中虽有“检查更新”入口，但默认关闭；不要把没有收到提示当作“已经是最新版本”。日常使用建议按下文手动核对发布清单并更新。

## 先确认是否有稳定新版本

1. 在桌面端的 **设置 → 关于** 中查看当前版本；如果应用无法启动，先记录当前安装包的版本及问题，不要凭猜测改写本机数据。
2. 打开[稳定发布清单](https://github.com/JavdBviewed/JavdBviewed-release/blob/main/manifests/desktop/stable.json)，确认 `releaseStatus` 是 `released`，查看 `latest.version`、`latest.tag` 和 Windows x64 `.exe` 资产。
3. 打开清单所指的[正式 Release 页面](https://github.com/JavdBviewed/JavdBviewed-release/releases)，对照版本、安装包文件名及发布说明。只有确认有高于本机版本的稳定安装包时才升级；清单无法获取时，不要依据主分支版本号推断已发布。

1.0.0 的已核稳定安装包是 `JavdBviewed-desktop-1.0.0-win-x64.exe`；对应的 `.blockmap` 和 `latest.yml` 供更新机制使用，**不是**需要手动运行的安装程序。未核实 macOS 或 Linux 稳定安装包时，不要用其他平台的文件替代。

## 升级前保留数据

1. 如连接了自己的 Cloud，先查看同步反馈，确认本机未处理的记录已同步；Cloud 服务端的数据库与配置应按[Cloud 备份指南](/cloud/backup-upgrade)单独备份。不要把“已登录”当作“已同步完成”。
2. 完全退出桌面应用，包括正在播放的窗口，避免备份时应用继续写入数据。
3. 备份**当前 Windows 用户的整份桌面端应用数据目录**，而不只是安装程序。1.0.0 在 Electron `userData` 中保存本地扫描、媒体源、播放进度及 Cloud 同步状态等数据；目录的具体位置应按当前安装和 Windows 用户环境核对，本页不指定可能错误的个人路径。
4. 本机视频文件和网络共享目录与应用数据不同，也要按照自己的存储方案另行备份。保存备份的日期、应用版本和原位置；备份中可能含账号凭据或同步信息，应限制访问，不要上传到公开问题帖。

备份完成后，确认备份副本可读取、应用数据没有被复制成只有快捷方式的空目录，再开始安装。需要回退时应使用**升级前**的数据副本；如果打算迁移到其他电脑，单独记录原有媒体目录的位置和 Cloud 实例地址。

只复制安装包**不是**备份本机资料。受 Windows 安全存储机制保护的媒体源凭据也不能保证在另一台电脑或另一 Windows 账号中恢复后直接可用；跨设备迁移时准备好重新登录和重新配置的凭据。

## 手动安装稳定版

1. 从稳定清单列出的 `downloadUrl` 下载对应版本的 **Windows x64 `.exe`**；1.0.0 可从[正式发布入口](/desktop/install)进入。不要从未经确认的镜像站、源码构建产物或开发分支下载。
2. 在安装包所在目录打开 PowerShell，计算文件的 SHA-256，并与稳定清单中**同一版本、同一 `.exe` 资产**的 `sha256` 值逐字对照：

   ```powershell
   $file = '.\JavdBviewed-desktop-1.0.0-win-x64.exe' # 其他版本请改成实际文件名
   (Get-FileHash -LiteralPath $file -Algorithm SHA256).Hash.ToLowerInvariant()
   ```

3. 对于 1.0.0，这个安装程序在稳定清单中的哈希是 `a8c0ac9b25cd10f3ea7ce6600047e74f61b5b103b4086a66836a2ed70340344c`；更新到**其他版本时必须读取该版本自己的哈希**，不能沿用此值。校验不符就停止安装，重新从正式 Release 下载并再次核对。
4. 确认应用已经退出后，运行已校验的 `.exe`，按安装程序提示完成安装。不要在安装过程中手动删除桌面端数据目录，也不要把旧安装包与新版本的 `.blockmap` 混用。
5. 启动桌面端，核对版本、原有本地目录、媒体源连接和 Cloud 同步反馈；实际打开一部可访问的影片，确认播放和进度正常。遇到媒体源要求重新登录时，先核对原连接，不要直接清空数据。

上述步骤不保证任何未来版本都能无损读取旧数据；若新版本发布说明要求额外迁移或备份，应以该版本说明为准。更新前可以先看[本地影片整理](/desktop/local-library)和[媒体源连接](/desktop/sources)，记录当前配置以便核对。

## 内置更新检查（可选）

固定发布源码确认：**已打包的桌面端**只有在启动时环境变量 `JAVDB_DESKTOP_UPDATE` 设置为 `1`、`true`、`yes` 或 `on` 时才允许通过 **设置 → 关于 → 检查更新** 发起查询；未设置或其他值均保持关闭。1.0.0 代码在启动时只配置更新器，**不会自行发起检查**，下载也不是在退出时自动安装。

仅需临时试用时，可在 PowerShell 会话里设置进程环境变量，再从**同一个会话**启动已安装的应用（路径按本机实际安装位置填写）：

```powershell
$env:JAVDB_DESKTOP_UPDATE = '1'
& '<已安装的 JavdBviewed.exe 的完整路径>'
```

以后从普通快捷方式打开时，该临时 PowerShell 设置不会随之生效；不需要开启时不要把它写入永久系统环境变量。启用也不表示新版本一定存在、下载一定成功或会静默安装。**日常升级仍以稳定清单和手动校验安装包为准**；不要设置用于开发测试的更新源或镜像覆盖变量。

## 更新失败或需要回退

| 情况 | 处理方式 |
| --- | --- |
| 找不到正式新版本或清单无法核实 | 暂停升级，保留当前应用与备份；不要以源码主分支或未知镜像代替正式发布 |
| SHA-256 与清单不符 | 不运行安装程序；核对文件名、版本、下载完整性和来源后重新下载 |
| 安装中断或新版本打不开 | 先记录安装/启动错误与版本，勿删除应用数据；回到正式 Release 核对安装包，再决定是否重装 |
| 原有目录、媒体源或同步记录看不到 | 先核对是否使用原 Windows 用户、原媒体目录和原 Cloud 实例，避免反复覆盖备份或重新确认入库 |
| 必须退回旧版 | 确认旧版安装包仍来自正式 Release 且哈希可信；关闭应用后另存**当前**数据副本，再考虑用升级前的整份备份恢复 |

**回退安装包不等于回退数据格式**。不要假定旧版能读取升级后写入的数据；如果只有升级后的资料而没有升级前备份，先停下恢复操作，保留数据副本并核对该版本的迁移说明。Cloud 数据还需要按服务端的备份与回滚流程处理，不随桌面端重新安装自动回退。
