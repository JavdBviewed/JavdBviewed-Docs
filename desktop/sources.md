# 媒体源与播放

桌面端 **Windows x64 1.0.0** 可以连接媒体源，在应用内浏览影片并播放。媒体源连接、[本地影片扫描](/desktop/local-library)和 Cloud 同步是不同入口：扫描目录不会自动把影片加入媒体库，连接媒体源也不会替你确认扫描结果。

本文以已发布的 1.0.0 桌面端为准。发布说明确认了 Emby 等媒体源的直连播放；设置表单另提供 Jellyfin 和本地文件夹类型。不要把桌面端的连接方式与[网页端 Emby 增强](/guide/emby-integration)混用，也不要将 115、WebDAV 等其他服务当作此版本已经支持的桌面媒体源。

## 选择连接方式

| 影片在哪里 | 在桌面端选择 | 填写什么 |
| --- | --- | --- |
| 自己的 Emby 服务器 | **媒体源连接 → Emby** | 从这台电脑可访问的服务器地址与账号，或 API key |
| 自己的 Jellyfin 服务器 | **媒体源连接 → Jellyfin** | 服务器地址与对应的登录信息；先测试实际连接和影片播放 |
| 当前电脑可访问的视频目录 | **媒体源连接 → 本地文件夹** | 目录的完整路径，可用“选择目录”选取 |

这里的“本地文件夹”是播放用的媒体源类型；**本地影片**页的添加目录、番号识别、刮削和确认入库则用于整理作品记录。两者互不代替。

## 添加 Emby 或 Jellyfin

1. 在桌面端打开 **设置 → 媒体源连接**，选择 **Emby** 或 **Jellyfin**。
2. 填写 **服务器地址**，例如 `https://media.example.com`；这是示例地址，请换成自己服务器的实际地址。可填显示名，便于区分多个连接。
3. 填写该媒体服务器的用户名和密码；若使用 API key，可在表单的可选字段填写。不要在文档、截图或公开反馈中粘贴真实凭据。
4. 点 **测试连接**，查看表单下方的连接状态，再点 **保存连接**。保存后检查下方列表中的条目是否已启用。
5. 打开桌面端媒体库，使用 **刷新** 加载影片。先检查影片列表和详情，再选一部确定在该服务器上可播放的影片验证。

服务器地址应指向**媒体服务器本身**，不是 Cloud 的地址或浏览器里某个影片详情页。要让桌面端访问，服务器及端口必须从运行桌面端的这台电脑可达；局域网地址在离开该网络后未必可用。使用 HTTPS 时还要确认服务器证书可正常校验。

> [!NOTE]
> 使用用户名和密码时，“测试连接”会请求服务器登录接口。**仅填写 API key** 时，1.0.0 的成功反馈是“连接配置已保存，稍后校验 API key”，不是已经验证该 key 能浏览或播放影片；保存后仍要实际加载媒体库并试播。

编辑已有连接时，密码或 API key 留空表示**保留本机已有凭据**，不是清除。若凭据已失效，请输入新的凭据并重新测试；不要仅凭“已保存”判断账号可用。

### 使用本地文件夹

在 **媒体源连接** 中选 **本地文件夹**，使用 **选择目录** 或填写当前电脑上的目录路径，再点 **测试连接**、**保存连接**。此处测试的是目录可访问性，不是 Emby 登录；不需要填写媒体服务器账号。

目录被移动、盘符改变或网络共享断开后，先在 Windows 文件管理器中确认路径仍可读取，再回设置页检查连接。这个媒体源的目录路径不参与 Emby/Jellyfin 媒体源配置的 Cloud 双向同步；另一台电脑要播放同一批本地文件，需要自行确保它能访问相应目录。

## 浏览和播放

媒体库需要有**已启用且可访问**的媒体源。打开影片列表、进入详情并选择播放操作；实际播放仍取决于影片文件、服务器返回的播放地址以及当前网络。Emby 直连播放属于桌面端功能，不需要先在网页端开启 Emby 增强。

如果媒体库提示“还没有启用的媒体源”，返回 **设置** 检查是否保存并启用连接；提示“已连接媒体源，但还没有可显示的 Movie 条目”，先查看服务器中是否确实有可供该账号访问的电影。加载失败时可点 **重试**，并根据错误回到 **打开设置** 核对地址与凭据。

观看本机目录中的影片会在本机保存播放进度；需要在设备间共享已看记录或进度时，还要连接自己的 Cloud 并确认同步成功。电影出现在扫描列表里不等于能从该列表直接播放，详见[整理本地影片](/desktop/local-library)。

## 需要 Cloud 同步时

**本机添加媒体源无需先登录 Cloud**。Cloud 是单独的 **设置 → Cloud 同步** 面板，填写自己的实例地址（示例：`https://cloud.example.com`）、本机设备名与 Cloud 管理员账号和密码，再点 **登录**；按需点 **立即同步**。

登录后，Emby/Jellyfin 的媒体源配置可从 Cloud 拉到本机，本机的相应媒体源变更也会进入同步流程。同步后在 **媒体源连接** 列表中核对条目，避免为同一服务器重复建源。Cloud 同步成功不等于 Emby/Jellyfin 服务器已可达或该影片必定能播放；仍需在当前电脑试连、查看媒体库和试播。Cloud 的部署与连接见[Cloud 指南](/cloud/)。

## 排查连接和播放问题

| 表现 | 优先检查 |
| --- | --- |
| 服务器地址无效 | 填媒体服务器的 HTTP/HTTPS 根地址，确认协议、域名和端口；不要填影片链接或 Cloud 地址 |
| 无法解析、连接超时或拒绝连接 | 从这台电脑确认域名解析、网络、端口及媒体服务器运行状态；局域网地址需要同网可达 |
| 证书校验失败 | 检查 HTTPS 地址和服务器证书配置，勿把异常证书提示当作账号错误 |
| 用户名或密码错误 | 核对媒体服务器账号；编辑原连接时如需换密，明确输入新密码后再测试 |
| API key 显示“稍后校验” | 该反馈未验证实际权限；保存后加载列表并试播，再排查 key 与服务器权限 |
| 连接保存了，媒体库仍为空 | 确认连接已启用、服务器有可见的电影条目，尝试“刷新”或“重新加载” |
| 有电影但无法播放 | 确认原服务器上该影片可访问，检查连接凭据、媒体文件和返回的播放地址 |
| 本机能播放，其他设备没有进度 | 核对两端是否连接同一 Cloud、登录及同步反馈；本机播放不等于云端已收到 |
