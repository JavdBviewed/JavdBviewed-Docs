# 整理本地影片

桌面端可以读取这台 Windows 电脑上的视频目录，按文件名识别番号，再通过已配置的刮削引擎补全作品信息。**扫描结果并不是已经入库的记录**：确认后才写入本机映射，并在连接 Cloud 时同步对应的作品记录。

本文按桌面端 **Windows x64 1.0.0** 的已发布功能说明。首次安装请先看[安装指南](/desktop/install)；想直接浏览和播放影片，请先区分这里的扫描列表与[媒体源](/desktop/sources)。

## 准备目录

- 确保视频文件就在当前电脑可访问的文件夹中；网络共享目录也要先确认 Windows 能正常访问，不要把 Cloud 地址填作本地目录。
- 文件名开头应有可识别的番号，例如 `SSIS-001` 或 `FC2-PPV-1234567`；识别失败的文件仍可能出现在列表中，但不能刮削或确认入库。
- 刮削需要可用的作品查询引擎和网络连接；不刮削也可对已正确识别番号的条目进行确认，先不要确认拿不准的作品。
- 扫描和本机保存不要求先登录 Cloud；跨设备共享作品记录、播放进度时才需要连接自己的 Cloud。

### 目录范围

桌面端扫描会读取目录内支持的视频文件及有限层级的子文件夹。常见格式如 `.mp4`、`.mkv`、`.avi`、`.ts`；隐藏目录和系统目录不会作为影片目录遍历。文件夹里有文件但列表为空时，先检查文件是否在已选目录下、扩展名是否属于视频格式、以及目录是否可读。

## 1. 添加目录或重扫

1. 打开桌面端的 **本地影片**。
2. 点 **浏览…** 选择本机文件夹，或在“目录路径”里填写 Windows 上的完整目录路径，然后点 **添加目录**。
3. 等待扫描结束，核对目录行显示的影片数量，并在文件行查看文件名、识别番号和状态。
4. 日后在同一目录加入或移动文件，可以对该目录点 **重扫**，再核对列表变化。

扫描只是读取影片目录并生成本机的条目；它不会替你把文件搬到媒体服务器。目录被移走、盘符变更或访问权限不足时，先在 Windows 中恢复目录可访问状态，再重扫。

> [!NOTE]
> “移除目录”会从桌面端的扫描记录中移除该目录和条目，不是清空磁盘文件。需要继续追踪时可重新添加目录；不要把移除操作当成删除视频文件。

## 2. 核对识别出的番号

识别到番号的文件会以待扫描条目出现；没有可识别番号的文件会标记失败。逐条对照文件名与实际作品，尤其是多文件、版本后缀或错误命名的情形。

| 看到的情况 | 应该怎么做 |
| --- | --- |
| 番号正确、状态待扫描 | 可以刮削补充资料，或确认后先保存番号记录 |
| 没有番号 | 核对文件名是否以受支持的番号开头；修正命名后重扫 |
| 番号与作品不符 | 暂时不要确认；先核对文件或文件名，避免错误资料进入记录 |
| 不想收录 | 在待扫描或已刮削条目上使用 **拒绝**；不会把这条记录写入 Cloud |

重扫会根据当前文件重新整理列表；磁盘上已经不存在的文件不会继续保留为扫描条目。已刮削、已入库或已拒绝条目的状态不会因普通重扫自动退回待扫描，因此改名后要核对新的条目和原有记录是否符合预期。

## 3. 刮削作品资料

1. 对番号正确、状态为待扫描的条目点 **刮削**。
2. 桌面端按已配置的引擎查询对应番号，成功时可以在条目下看到标题等资料，状态变为“已刮削”。
3. 对照实际作品再决定是否确认；标题、封面或日期与文件不符时，先检查番号和引擎，不要直接入库。

出现“无可用刮削引擎”或“未找到结果”时，条目仍留在待扫描状态，可以配置或更换引擎后重试。刮削失败不等于本地文件丢失，也不意味着可以忽略错误资料继续确认。

## 4. 确认入库与去重

确认前先核对番号和已获取的资料。待扫描或已刮削、且有番号的条目可点 **确认入库**；成功后该条目标记“已入库”，本机保存文件与番号的映射。

- **尚未登录 Cloud**：本机仍保存入库结果，操作反馈为“待登录后同步到云”；之后登录并完成同步即可，不必重复确认同一文件。
- **已经登录 Cloud**：确认会把对应的作品记录放入待同步队列，并触发同步；通过同步状态或操作反馈判断是否成功，不要把“本机已入库”误当成“云端已收到”。
- **同一个番号的多个文件**：本机每个扫描文件有自己的条目；Cloud 中作品记录以番号为身份，已有记录不会因为重复确认而新增一份同番号作品。已有的其他来源信息也不会仅因本机扫描而无条件覆盖。

确认失败时先读条目的错误信息：没有番号的文件无法入库；已经入库的同一条目重复确认不会再次创建一份。扫描列表中的“入库”是**作品记录**，不是把视频文件上传或导入到 Emby/Jellyfin 的媒体库。

## 本机文件与 Cloud 记录

就这条“本地目录扫描 → 确认 → Cloud 同步”流程而言，桌面端在本机遍历目录并保存扫描条目；上行构造的是作品实体，包括番号、标题或刮削得到的封面等资料，以及来源标识。**同步作品记录不等于上传视频文件本体**；影片仍由当前电脑上的目录或你自行接入的媒体源提供。

这也不意味着“Cloud 不保存任何业务信息”：在启用同步后，记录及进度会进入你自己的 Cloud 实例。使用前确认该实例的存储与备份由谁负责，详见 [Cloud 部署与备份](/cloud/)。本机目录的扫描也不会自动创建媒体源连接。

## 播放进度与真实已看

本地影片页用于整理文件和番号，**不是从扫描行直接播放的入口**。要在桌面端播放本机视频，可在设置的 **媒体源连接** 中另加“本地文件夹”类型；观看 Emby/Jellyfin 内容则添加对应服务器。具体见[媒体源与播放](/desktop/sources)。

播放本地媒体源的影片时，桌面端会在本机保存进度。对于能从文件名识别出番号的影片，连接 Cloud 后，进度可随同步上行；满足播放完成条件时，会同步“真实已看”的状态。没有可识别番号、Cloud 未连接或同步失败时，不要假定其他设备已收到进度；先确认本机播放记录和 Cloud 同步状态。

“确认入库”与“真实已看”是两件事：前者收录作品记录，后者来自实际播放。仅扫描或刮削一部影片，不会自动将它标记为已看。

## 常见问题

| 表现 | 检查顺序 |
| --- | --- |
| 添加目录提示不存在或不可访问 | 在 Windows 文件管理器中打开同一路径；确认选中的是目录且磁盘或共享位置可访问 |
| 目录存在但没有发现影片 | 检查扩展名、子文件夹层级、隐藏目录及读取权限；核对路径后重扫 |
| 文件出现但显示失败 | 先核对文件名开头的番号；无番号时不能刮削或确认 |
| 刮削提示无引擎或没有结果 | 检查引擎配置、番号和网络；条目保持待扫描，可调整后重试 |
| 已入库但另一台设备看不到 | 区分本机保存与 Cloud 同步，核对 Cloud 登录、同步反馈及两端连接的实例 |
| 能看到扫描条目但不能播放 | 扫描列表不是媒体库播放入口；检查是否另行接入本地文件夹或 Emby/Jellyfin 媒体源 |
| 播放后未标记真实已看 | 确认影片能识别番号、播放确实满足完成条件、Cloud 连接与同步是否正常 |
